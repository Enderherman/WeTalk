# 同账号多端消息同步

## 分发范围与视角

2026-10-04：同一账号允许一个浏览器和一个桌面客户端同时在线。私聊 type **2（文字）/5（媒体占位）/6（上传完成）** 各向两个账号的全部在线连接分发一次：

| 字段 | 接收方设备 | 发送方设备（包括发起 HTTP 的设备） |
|---|---|---|
| `messageId`、`sessionId` | 同一服务器消息/会话 | 保持相同 |
| `sendUserId`、`sendUserNickName` | 实际发送者 | 保持实际发送者，客户端据此识别本人消息 |
| `contactId` | 发送者编号 | 原始收件人编号，不能改成发送者自己 |
| `contactName` | 发送者真实昵称 | 本人会话中的收件人真实名称；未知时不填，客户端保留已有名称 |
| `clientMessageId` | 原始文字幂等键（存在时） | 与 HTTP 返回相同，供待发队列确认 |

各方使用独立 DTO 副本。查找发送方会话时只读取 `contactName`，不会把私有 `remark` 放进消息或接收方数据。无关账号不接收事件。

type 17（已读回执）和 type 18（私有备注）保持原有定向控制语义，不进行发送方额外镜像；其他控制事件同样不自动镜像。群聊本来就通过群通道覆盖发送者设备，不再叠加私聊镜像；发送者和收件人为同一编号时也不会重复分发。

## type 6 最终文件元数据

完成通知在文件持久化事务提交后发送，复制最终 `ChatMessage` 字段，仅把事件的 `messageType` 改为 6：

- `messageId`、`sessionId`、`contactType`、按上述视角转换的 `contactId`。
- `sendUserId`、`sendUserNickName`、原始 `sendTime`、`messageContent`。
- `status=1`、最终 `fileName`、真实 `fileSize`、`fileType`。

不包含服务器绝对路径。数据库中该消息仍为 type 5；客户端可用 type 6 将对应媒体占位合并为已发送状态，收到完整完成事件时亦可恢复遗漏的占位。字段缺失不能覆盖已知值，实际存在的最终文件字段应覆盖旧占位元数据。

## AI 提问

向 Urobot 发送的提问在插入后也发布 type 2，两个本人设备使用同一服务器消息 ID 和幂等键，`contactId=Urobot`，名称为当前系统机器人配置。随后仍通过 14/15/16 同步初始化、流式累计文本和终态。提问不会变成自聊，也不会等到机器人最终回复才出现在另一端。

## 客户端合并要求

HTTP 成功响应和 WS 回显可能乱序到达。两端都应按服务器 `messageId` 去重，并利用原 `clientMessageId` 确认待发记录；同一个本人消息只展示一次且不增加未读。type 6 应按消息 ID 合并最终元数据，不创建第二条文件消息。控制帧不能作为新聊天消息插入。

## 验证范围

新增 `SameAccountFanoutTest` 8 项和 `MultiDeviceMessagePayloadTest` 2 项：发送/接收方浏览器与桌面各通道视角、原 DTO 不变、私有备注不泄露、未知联系人名、17/18 控制帧、群/自收不重复、AI 提问顺序和 HTTP ID 一致、文件完成的最终字段及提交后发布。修复前 6 项失败，修复后全量 196 项通过。真实 HTTP/WebSocket 与两端 UI 乱序合并由隔离环境联调另记。
