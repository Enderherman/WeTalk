# 附件上传状态、权限与重试

2026-10-04 整体验证补齐。

- 创建文件消息必须包含合法文件名、正数文件大小和 0/1/2 文件类型；不能把文本消息作为附件占位。
- 上传仅允许原发送者，并重新查询当前双向好友或群成员关系；删除、拉黑、退群后不能继续填充旧占位消息。
- 拒绝空文件、路径/控制字符、过长文件名和未知类型。配额同时约束声明类型与图片/视频扩展名，不能把图片或媒体改为 `.txt` 来放宽大小限制。
- 图片消息要求扩展名、MIME 和文件签名一致，封面沿用同样验证。
- 同一消息的上传以数据库行锁串行处理，先在临时文件完整接收；文件消息提交前不可下载，上传完成通知在数据库提交后发送。
- 成功后的同名、相同字节重试直接成功，不重复写消息或广播；换字节/换文件名会拒绝，不能修改已发送附件。
- 临时文件在成功、拒绝或传输失败后清理；失败传输保持消息为待上传，可用原消息 ID 重试。

验证：新增 14 项上传回归与 1 项待上传/非附件下载拒绝回归，`mvn -B -ntp clean verify` 全量 **184/184** 通过。

独立 MySQL/Redis/Spring 实例的真实 HTTP 六组全部通过：类型/元数据拒绝、未完成下载/非发送者/空文件拒绝、同字节重试与不可替换、真实 PNG 字节与 MIME、有效 WAV 的 Range 首段/尾段/416/越权拒绝，以及退群后上传拒绝。测试附件均为本机隔离数据，生产库与 NAS 未修改。
